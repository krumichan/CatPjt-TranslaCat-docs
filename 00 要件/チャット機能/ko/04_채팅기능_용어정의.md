# 채팅 기능 용어 정의

## userId
시스템 내부 DB 식별자. 관계 저장과 내부 API 참조에 사용한다. 일반 사용자가 직접 입력하는 식별자로 사용하지 않는다.

## publicId
TranslaCat 사용자 공개 식별자. 사용자 검색, 친구 추가, 프로필 표시의 기준이다.

예: `TC-H6VR-9KQD`

## roomType
- `DIRECT`: 1:1 채팅
- `GROUP`: 그룹 채팅

## sourceType
- `MANUAL`: Phase 1 수동 멤버 지정
- `FRIEND`: Phase 1.5 친구 관계 기반
- `OPEN`: Phase 2 공개 채팅 예정
- `AI`: Phase 2 AI 채팅 예정

`roomType`과 `sourceType`은 별개다.

## FRIEND DIRECT
- `DIRECT + FRIEND`
- 친구 관계가 필요
- 동일 사용자 조합의 기존 FRIEND DIRECT 재사용
- MANUAL DIRECT는 재사용하지 않음

## FRIEND GROUP
- `GROUP + FRIEND`
- 친구 목록에서 복수 선택
- 생성자 OWNER, 선택 친구 MEMBER
- 비친구/차단 관계는 멤버 추가 불가
- Phase 1.5에서는 동일 멤버 구성의 중복 생성 허용

## 친구 요청 상태
- `PENDING`
- `ACCEPTED`
- `REJECTED`
- `CANCELED`

## 친구 관계
요청 수락 후 생성되는 논리적 양방향 소셜 관계. DIRECT 시작 및 GROUP 멤버 선택 기준이다.

## 차단 관계
방향성을 가진 관계. 친구 요청, FRIEND 채팅 시작, GROUP 선택을 제한한다. 차단 시 친구 목록에서 제외하며, 해제 후 친구 관계는 자동 복구하지 않는 것을 기본 정책으로 한다.

## 멤버 역할
- `OWNER`: 방 소유자/생성자
- `MEMBER`: 일반 멤버

## 번역 상태
- `PENDING`
- `COMPLETED`
- `FAILED`

번역 실패 시에도 원문 메시지는 유지한다.

## Real Integration E2E
실제 인증 상태, BE API, DB 관계, WebSocket을 사용하는 결합 테스트. Phase 1.5에서는 3개 실제 테스트 계정으로 친구 요청 → 수락 → DIRECT → GROUP → 차단을 검증한다.
