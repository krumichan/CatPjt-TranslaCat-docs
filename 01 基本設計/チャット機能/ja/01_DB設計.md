# チャット機能 DB設計

## 1. 目的

Phase 1の既存チャット構造を維持しつつ、Phase 1.5のプロフィール、友達リクエスト、友達関係、ブロック関係を拡張する。

## 2. 設計原則

1. 認証ユーザー基準エンティティは既存 `user` を使用する。
2. 公開識別子は `user.public_id` を使用する。
3. 共通プロフィールは `user_profile` に分離する。
4. 友達リクエストと友達関係を分離する。
5. ブロックは方向性のある関係として管理する。
6. FRIENDチャットは既存 `chat_room`, `chat_room_member` を再利用する。
7. `room_type` と `source_type` を分離する。
8. Phase 2オープンチャット/AI/仮想プロフィールと直接結合しない。

## 3. テーブル一覧

| 領域 | テーブル | 説明 |

| ソーシャル | `friend_request` | 友達リクエスト |
| ソーシャル | `friend` | 友達関係 |
| ソーシャル | `user_block` | ブロック関係 |

| チャット | `chat_room_member` | メンバー |
| チャット | `chat_message` | メッセージ |
| チャット | `chat_message_translation` | 翻訳結果 |

## 4. user_profile

| カラム | 説明 | 制約 |
|---|---|---|
| `id` | PK | PK |
| `user_id` | ユーザーID | FK, UNIQUE |
| `nickname` | ニックネーム | NOT NULL |
| `profile_image_url` | プロフィール画像URL | NULL可 |
| `bio` | 自己紹介/ステータスメッセージ | NULL可 |
| `created_at` | 作成日時 | NOT NULL |
| `updated_at` | 更新日時 | NOT NULL |
| `deleted_at` | 削除日時 | NULL可 |

方針:
- `user` と論理1:1
- publicIdは `user.public_id` を使用
- 現在の画像はURL方式
- ファイルアップロードと背景画像は後続Issueで拡張
- Phase 2仮想プロフィールと分離

## 5. friend_request

| カラム | 説明 |
|---|---|
| `id` | PK |
| `requester_user_id` | 送信者 |
| `receiver_user_id` | 受信者 |
| `status` | リクエスト状態 |
| `requested_at` | リクエスト日時 |
| `responded_at` | 応答/キャンセル日時 |
| `created_at` | 作成日時 |
| `updated_at` | 更新日時 |
| `deleted_at` | 削除日時 |

状態:
- `PENDING`
- `ACCEPTED`
- `REJECTED`
- `CANCELED`

方針:
- 自分自身へのリクエスト禁止
- 既に友達のユーザーへのリクエスト禁止
- 同一関係のPENDING重複禁止
- 双方向のいずれかにブロック関係がある場合は禁止
- 承認時に友達関係作成
- 拒否/キャンセルは履歴維持後に状態変更

## 6. friend

| カラム | 説明 |
|---|---|
| `id` | PK |
| `user_id` | 基準ユーザー |
| `friend_user_id` | 友達ユーザー |
| `created_at` | 作成日時 |
| `updated_at` | 更新日時 |
| `deleted_at` | 削除日時 |

方針:
- サービス観点では論理的な双方向関係
- 同一 `user_id`, `friend_user_id` 組み合わせの重複禁止
- 取得/削除時に双方向関係を一貫処理
- リクエスト承認時に作成
- 友達削除後も既存ルーム/メッセージは削除しない

## 7. user_block

| カラム | 説明 |
|---|---|
| `id` | PK |
| `blocker_user_id` | ブロックしたユーザー |
| `blocked_user_id` | ブロックされたユーザー |
| `created_at` | 作成日時 |
| `updated_at` | 更新日時 |
| `deleted_at` | 削除日時 |

方針:
- 自分自身のブロック禁止
- 同一ユーザー重複ブロック禁止
- active `(blocker_user_id, blocked_user_id)` 重複防止
- 友達リクエスト制限
- FRIEND DIRECT新規開始制限
- GROUPメンバー追加制限
- ブロック時に友達一覧から除外
- 解除後の友達関係は自動復旧しないことを基本とする

## 8. 既存チャットテーブル接続

### chat_room
主要論理フィールド:
- `room_type`: `DIRECT`, `GROUP`
- `source_type`: `MANUAL`, `FRIEND`, 将来 `OPEN`, `AI`
- `name`
- `description`
- `owner_id`
- `active`

### chat_room_member
- ルームとユーザーのメンバーシップ
- `OWNER`, `MEMBER`
- FRIEND GROUP作成者はOWNER、選択友達はMEMBER

### chat_message
- 原文メッセージ
- 送信者情報
- cursor pagination基準

### chat_message_translation
- メッセージ別言語別翻訳
- `PENDING`, `COMPLETED`, `FAILED`

## 9. FRIEND DIRECT接続

```text
friend関係確認
      ↓
chat_room
  room_type = DIRECT
  source_type = FRIEND
      ↓
chat_room_member
  user A
  user B
```

- 対象は友達であること
- 双方向ブロック関係なし
- 同一ユーザー組み合わせ + DIRECT + FRIEND既存ルームを再利用
- MANUAL DIRECTは別ルーム

## 10. FRIEND GROUP接続

```text
友達B/C選択
      ↓
友達/ブロック関係検証
      ↓
chat_room
  room_type = GROUP
  source_type = FRIEND
      ↓
A = OWNER
B/C = MEMBER
```

- 全対象は現在友達
- ブロック関係ユーザーを含めない
- ログインユーザーはサーバーでOWNER追加
- Phase 1.5では同一メンバー構成グループの重複作成を許可

## 11. 主要整合性基準

- `user_profile.user_id` UNIQUE
- active friend組み合わせの重複防止
- active user_block組み合わせの重複防止
- 自分自身対象リクエスト/ブロック禁止
- 同一関係PENDING重複防止
- FRIEND DIRECT再利用基準: ユーザー組み合わせ + DIRECT + FRIEND
- ルーム単位で同一ユーザーメンバー重複禁止

## 12. Phase 1.5除外DB

- オープンチャット詳細設定
- オープンチャット仮想プロフィール
- AIメンバー/persona
- 既読/未読
- typing indicator
- オンライン状態
- 通報/運営者/強制退室
- Redisセッション/購読状態

## 13. マイグレーション原則

- 既存MANUALデータ維持
