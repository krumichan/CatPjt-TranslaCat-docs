# チャット機能 FE画面設計

## 1. 目的

Phase 1基本チャットとPhase 1.5友達ベースソーシャルチャットのユーザーフロー、Route、状態表示、API連携基準を定義する。

## 2. 画面一覧

| 画面/機能 | Route | 説明 |
|---|---|---|
| チャットルーム一覧 | `/chat` | MANUAL/FRIENDルーム一覧 |
| チャットルーム詳細 | `/chat/rooms/{roomId}` | メッセージ/翻訳/言語設定 |
| 友達一覧 | `/friends` | 友達一覧、DIRECT、グループ選択 |
| ユーザー検索 | `/friends/search` | publicId検索/友達リクエスト |
| グループ作成 | `/friends/group/new` | 選択友達ベースのグループ作成 |
| プロフィール設定 | `/settings/profile` | 自分のプロフィール取得/修正 |
| 友達リクエスト通知センター | `/friends` 内Modal | 受信/送信リクエスト処理 |
| ブロック管理 | 友達画面関連UI | ブロック/一覧/解除 |

## 3. 全体フロー

友達追加:

```text
/friends
  ↓ ユーザー検索
/friends/search
  ↓ publicId検索
検索結果
  ↓ 友達リクエスト
PENDING
  ↓ 相手通知センター
承認
  ↓
友達一覧反映
```

FRIEND DIRECT:

```text
/friends
  ↓ 友達カード 1:1チャット
POST /chat/friends/{friendUserId}/direct-room
  ↓
/chat/rooms/{roomId}
```

FRIEND GROUP:

```text
/friends
  ↓ グループ選択
友達複数選択
  ↓ グループ作成
/friends/group/new
  ↓ グループ名/説明
POST /chat/friends/group-rooms
  ↓
/chat/rooms/{roomId}
```

## 4. プロフィール画面

Route: `/settings/profile`

表示:
- publicId
- nickname
- profileImageUrl
- bio

アクション:
- 取得
- 修正
- 保存
- 失敗時Retry

状態:
- Loading
- 取得成功
- 修正中
- 保存成功
- validation
- API Error
- Retry

## 5. ユーザー検索

Route: `/friends/search`

構成:
- publicId入力
- 検索ボタン
- 結果カード
- 友達リクエストボタン
- 関係状態

validation:
- 空publicId検索を防止

状態:
- 初期
- Loading
- 成功
- ユーザーなし
- 既に友達
- リクエスト完了
- リクエスト失敗

## 6. 友達リクエスト通知センター

`/friends` の通知ボタンからDialog/Modalで提供する。

機能:
- 受信リクエスト
- 送信リクエスト
- 承認
- 拒否
- キャンセル

承認フロー:
1. 承認クリック
2. API完了
3. リクエスト項目削除
4. 友達一覧refetch

実結合テストでは、リクエスト項目が消えたことを確認してから相手ユーザーの友達一覧を再取得する。

## 7. 友達一覧

Route: `/friends`

友達カード:
- nicknameまたは現在提供可能な表示情報
- publicId
- profile image
- 1:1チャット
- 友達メニュー: 削除/ブロック

上部アクション:
- ユーザー検索
- 通知センター
- グループ選択

状態:
- Loading
- 一覧
- 検索フィルター
- Empty
- Error/Retry

## 8. グループ選択モード

`/friends` 内で動作する。

- 選択モード開始
- 友達カード選択/解除
- 選択数表示
- `グループ作成 (N)` CTA
- ブロックユーザーを一覧から除外

FEフィルターとは別にBEで友達/ブロック関係を再検証する。

## 9. FRIEND GROUP作成

Route: `/friends/group/new`

入力:
- 選択友達表示
- グループ名
- 説明
- グループチャット作成

validation:
- グループ名必須
- 選択メンバー有効性
- 非友達メンバー除去/ブロック
- API失敗時エラー + Retry

成功:

```text
POST /api/v1/chat/friends/group-rooms
  ↓ room.id
/chat/rooms/{roomId}
```

## 10. チャットルーム一覧

Route: `/chat`

表示:
- MANUAL DIRECT
- MANUAL GROUP
- FRIEND DIRECT
- FRIEND GROUP

移行方針:
- 一般ユーザー向けuserId直接入力ルーム作成UIは非公開
- `友達とチャット開始` CTAは `/friends` へ移動
- 既存MANUALルームは継続アクセス可能

## 11. チャットルーム詳細

Route: `/chat/rooms/{roomId}`

機能:
- ルーム情報
- 初期メッセージ
- cursor過去メッセージロード
- ID基準重複除去
- メッセージ送信
- WebSocket受信
- WebSocket未接続時REST fallback
- 翻訳状態
- translation.completed反映
- ルーム言語設定取得/保存

状態:
- メッセージEmpty
- PENDING
- COMPLETED
- FAILED + 原文維持
- 送信失敗
- 言語保存失敗

## 12. Loading / Empty / Error

Loading:
- プロフィール
- 検索
- 友達一覧
- リクエスト一覧
- ブロック一覧
- ルーム一覧/詳細
- メッセージ追加ロード
- グループ作成/メッセージ送信

Empty:
- 検索結果なし
- 友達なし
- 受信/送信リクエストなし
- ブロックユーザーなし
- チャットルームなし
- メッセージなし

Error:
- エラーメッセージ
- 可能な場合Retry
- ユーザー入力および原文維持

## 13. レスポンシブ/ダークモード

主要画面をPC/モバイルおよびダークモード基準で簡易確認した。

注意:
- 長いpublicId overflow
- 長いnickname
- 友達カードアクション
- Modal内部スクロール
- グループ選択カード
- グループ作成フォーム
- モバイル固定幅Modal防止
- ダークモード文字コントラスト

## 14. i18n

主要Social/Chat画面は `ko`, `ja` localeをサポートする。E2Eで両locale主要画面の翻訳keyエラーを確認する。
