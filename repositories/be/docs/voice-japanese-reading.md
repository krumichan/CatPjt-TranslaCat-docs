# Voice 일본어 원문 읽기 표기

Voice의 확정 번역 AI에는 번역문만 요청한다. 일본어 원문의 `sourceReadingTokens`는 BE가 기존 Sudachi full 사전으로 로컬 생성한다. 읽기 표기를 위해 AI API를 추가 호출하지 않는다. 임시 인식·번역(`TRANSCRIPT_PARTIAL`)에는 읽기 분석을 하지 않아 미리보기 지연을 늘리지 않는다.

BE는 일본어로 판정한 `TRANSCRIPT_FINAL`에서 읽기 토큰을 생성해 이벤트와 세그먼트 이력에 함께 기록한다. 따라서 확정 원문은 번역 완료를 기다리지 않고 루비를 표시할 수 있다. `VOICE_PIPELINE_COMPLETED`와 실패한 번역의 재시도에서도 같은 원문 기준으로 토큰을 생성하며, 번역 완료 시 분석에 실패하면 이미 저장된 유효한 토큰을 유지한다. 언어가 명확하지 않거나 일본어가 아니면 읽기 토큰을 비운다.

운영 `whisper-1`은 지원 언어를 확인해도 수치 신뢰도와 채널 잠금이 모두 비어 있을 수 있다. 번역 단계까지 진행한 실패 발화의 재시도에서는 저장된 감지 언어가 지원 언어이고 잠금이 없거나 같은 언어일 때 이를 재사용한다. 수치 신뢰도가 없는데 감지 언어와 과거 잠금이 다르면 실제 번역 입력 언어를 확정할 수 없으므로 재시도를 거절한다. 이 경우를 정확히 복원하려면 AI가 선택한 입력 언어를 별도 필드로 전달·저장하는 계약이 필요하다.

각 토큰은 `{ "surface": "日本", "reading": "にほん" }` 형식이다. 공백·줄바꿈·문장부호에는 `reading: null`을 사용한다. 모든 `surface`를 순서대로 연결한 값은 `sourceText`와 정확히 같아야 한다. Sudachi의 원문 오프셋으로 건너뛴 문자를 보충하고, 이 일치 조건이 깨지면 토큰을 버려 원문 표시를 보호한다. Voice 이벤트에 HTML 루비를 넣지 않는다. FE는 공백을 보존하고, 오래된 불완전 토큰을 받으면 원문 텍스트로 대체한다.

Sudachi 분석은 메모리에서 수행하며, 공유 tokenizer 접근은 동기화한다. 비정상적으로 긴 원문 또는 지나치게 많은 토큰, 사전 분석 오류는 읽기 표기만 생략하고 인식·번역·저장은 계속한다. 형태소 단위의 읽기이므로 고유명사와 문맥에 따른 다의어 읽기는 사전 한계가 있으며 번역문 정확도를 보장하지 않는다.

운영 반영 시에는 FE의 공백 보존 수정본을 먼저 배포하고, BE의 Voice 변경만 포함한 빌드를 적용한다. 적용 후 실제 일본어 탭 오디오로 `TRANSCRIPT_FINAL`의 읽기 토큰, 번역 완료, 이력 조회, 세션 종료를 확인한다. 일반 `/api/v1/health` 응답만으로 Sudachi 읽기 기능을 검증했다고 판단하지 않는다.
