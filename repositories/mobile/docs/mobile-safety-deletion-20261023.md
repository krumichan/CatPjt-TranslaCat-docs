# 신고·차단 표시·계정 탈퇴 연결

# 通報・ブロック表示・アカウント退会の接続

## 사용자 결정과 현재 상태

## ユーザーの決定と現在の状態

사용자는 계정 탈퇴와 데이터 삭제의 웹·앱 연결을 요청했다. 공동 채팅의 메시지·번역 본문은 유지하고 작성자를 `탈퇴한 사용자`로 표시한다. 운영자 전용 신고 증거는 접수 후 90일 보관한 뒤 자동 삭제하며, 개인 정보를 제거한 처리 기록만 남긴다. 공동 가계부는 다른 활성 참여자에게 소유권을 이전하고 공동 내역을 유지하며 탈퇴자의 표시를 익명화한다. 개인 가계부·개인 학습·프로필·연결 계정·친구/차단 관계·세션·기기 연결·개인 문의는 정리한다.

ユーザーはアカウント退会とデータ削除のウェブ・アプリ接続を依頼した。共有チャットのメッセージ・翻訳本文は維持し、投稿者を `탈퇴한 사용자`（退会したユーザー）として表示する。運営者専用の通報証拠は受け付けから 90 日保管してから自動削除し、個人情報を除いた処理記録だけを残す。共有家計簿は他の有効な参加者に所有権を移し、共同履歴を維持して退会者の表示を匿名化する。個人家計簿・個人学習・プロフィール・連携アカウント・友達 / ブロック関係・セッション・端末接続・個人問い合わせは整理する。

현재 구현과 구성 요소 검증, 새 APK 공유·다운로드 대조를 완료했다. 운영 배포, 기능 활성화와 실기기 수락은 별도 완료 영수증을 확인해야 한다. 실제 이용자의 탈퇴 요청을 시험 삼아 실행하지 않는다. 개발 채팅의 변경은 unstaged로 보존하고 배포는 전담 `배포 책임과 규칙 기억하기`가 담당한다.

現在、実装と構成要素の検証、新 APK の共有・ダウンロード照合は完了した。本番デプロイ、機能有効化と実機受け入れは別の完了記録を確認する必要がある。実ユーザーの退会要求を試験として実行しない。開発チャットの変更は unstaged で保存し、デプロイは専任の「배포 책임과 규칙 기억하기」が担当する。

## 앱과 웹의 흐름

## アプリとウェブの流れ

설정에서 계정 탈퇴를 선택하면 삭제되는 정보와 남는 공동 기록을 먼저 안내한다. 앱은 무작위 작업 번호와 32바이트 조회 비밀을 SecureStore에 저장하고 다시 읽어 확인한 다음 공식 웹의 탈퇴 화면을 연다. 조회 정보는 URL fragment로만 전달하며 웹이 즉시 주소에서 제거한다. 앱에 파괴적 탈퇴 POST를 구현하지 않는다.

設定でアカウント退会を選ぶと、削除される情報と残る共同記録を先に案内する。アプリはランダムな作業番号と 32 バイトの照会用秘密情報を SecureStore に保存し、読み戻して確認してから公式ウェブの退会画面を開く。照会情報は URL fragment だけで渡し、ウェブは直ちにアドレスから取り除く。アプリに破壊的な退会 POST は実装しない。

웹에서는 현재 계정의 TranslaCat ID와 앱에서 선택한 ID가 같아야 한다. 비밀번호 또는 Google의 별도 `DELETE_ACCOUNT` 본인 확인을 새로 수행하고, 안내 확인 및 본인 ID 입력 후 최종 버튼을 누른다. 본인 확인 결과는 현재 사용자·로그인 세션·목적에 묶이며 5분 안에 사용한다. 다른 계정으로 로그인된 경우 계정 전환 안내만 표시한다. Google 탈퇴 확인은 기존 로그인 세션을 다른 계정으로 바꾸지 않는다.

ウェブでは現在のアカウントの TranslaCat ID とアプリで選択した ID が一致する必要がある。パスワードまたは Google の別目的 `DELETE_ACCOUNT` 本人確認を新しく行い、案内確認および自分の ID 入力後に最終ボタンを押す。本人確認結果は現在のユーザー・ログインセッション・目的に結び付け、5 分以内に使用する。別アカウントでログインしている場合はアカウント切り替え案内だけを表示する。Google の退会確認は、既存ログインセッションを別アカウントに変更しない。

웹은 전송 전에 영수증에 전송 여부를 기록한다. 응답이 유실되면 요청을 자동 재전송하지 않고 같은 영수증으로 처리 상태만 확인한다. 영수증이 있는 탭에 다른 작업의 fragment가 들어와도 기존 기록을 덮어쓰지 않는다. 명시적인 두 단계 확인으로 로컬 영수증을 지울 수 있지만, 이미 접수한 서버 작업은 계속된다. 접수 이후 모든 기기의 로그인을 종료하므로 공개 탈퇴 화면은 로그인 해제 후에도 처리 결과를 표시한다.

ウェブは送信前に処理票へ送信の有無を記録する。応答を失った場合は要求を自動再送せず、同じ処理票で処理状態だけを確認する。処理票のあるタブへ別作業の fragment が入っても既存記録を上書きしない。明示的な 2 段階確認でローカル処理票を消せるが、既に受け付けたサーバー作業は継続する。受け付け後は全端末のログインを終了するため、公開退会画面はログアウト後も処理結果を表示する。

앱도 화면 활성 상태에서 영수증으로 처리 상태를 조회한다. 처리 중과 완료를 구분하며 서버의 PENDING을 완료로 바꾸어 표시하지 않는다. 완료 영수증은 완료 후 7일간 조회할 수 있다. 비밀 값·실제 토큰·신고 본문을 소스, 로그, 공개 설정이나 문의 문서에 기록하지 않는다.

アプリも画面が有効な間、処理票で処理状態を照会する。処理中と完了を区別し、サーバーの PENDING を完了に変えて表示しない。完了した処理票は完了後 7 日間照会できる。秘密値・実トークン・通報本文をソース、ログ、公開設定や問い合わせ文書に記録しない。

## 신고와 차단 표시

## 通報とブロック表示

메시지 메뉴 또는 사람 참여자의 메뉴에서 신고 사유와 설명을 작성하고, 확인 화면의 최종 버튼으로 한 번 접수한다. 취소는 쓰기를 하지 않는다. 결과 불명 후 사용자가 재시도하는 경우 동일한 UUID와 확정된 본문을 사용한다. 작성자 자신·시스템 메시지·숨긴 메시지·탈퇴 작성자에 대한 새 신고는 UI에서 제외한다. AI 메시지는 신고할 수 있고 AI 참여자 자체를 사람으로 신고하지 않는다.

メッセージメニューまたは人間の参加者メニューから通報理由と説明を記入し、確認画面の最終ボタンで 1 回受け付ける。キャンセルは書き込みを行わない。結果不明後にユーザーが再試行する場合は、同じ UUID と確定した本文を使う。投稿者本人・システムメッセージ・非表示メッセージ・退会投稿者への新規通報は UI から除外する。AI メッセージは通報できるが、AI 参加者自体を人として通報しない。

OPEN 참여자 신고에는 방 안의 멤버 ID를 사용한다. 운영자 웹은 ADMIN 및 서버 권한을 확인한 후 목록·증거·처리 상태·메모를 제공한다. 상태 변경에는 버전을 포함하고 결과 불명 시 상세를 다시 읽기 전 중복 저장을 막는다. 신고 상태 변경만으로 계정을 자동 제재하지 않는다. 증거 기한이 지나면 작업자가 지연돼도 읽기 응답에서 증거·검토 메모를 숨긴다.

OPEN 参加者の通報にはルーム内のメンバー ID を使う。運営者ウェブは ADMIN およびサーバー権限を確認してから一覧・証拠・処理状態・メモを提供する。状態変更にはバージョンを含め、結果不明の場合は詳細を再取得するまで重複保存を防ぐ。通報状態の変更だけでアカウントを自動制裁しない。証拠期限を過ぎた場合、worker が遅延していても読み取り応答から証拠・レビューメモを隠す。

차단 기간에는 양쪽의 메시지 본문·번역·프로필 표시를 가리고 알림·미읽음·배지에 반영하지 않는다. 해제하면 다시 표시할 수 있도록 원문을 파괴하지 않는다. 웹·앱은 `contentVisibility=VISIBLE|BLOCKED|MODERATED`와 `authorDeleted`를 처리하며 늦게 도착한 번역이 가린 내용을 되살리지 못하게 한다.

ブロック期間中は双方のメッセージ本文・翻訳・プロフィール表示を隠し、通知・未読・バッジに反映しない。解除すれば再表示できるよう原文は破壊しない。ウェブ・アプリは `contentVisibility=VISIBLE|BLOCKED|MODERATED` と `authorDeleted` を処理し、遅れて届いた翻訳が隠した内容を復活させないようにする。

## 서버 삭제와 배포 경계

## サーバー削除とデプロイ境界

BE가 탈퇴 접수를 영속 저장하고 CHAT·LL·BE 데이터·BE 파일 정리를 같은 작업 번호로 재시도한다. 접수 계정은 즉시 비활성화되고 늦게 끝난 요청과 작업자가 정보를 다시 저장하지 못하도록 각 서비스의 쓰기 경계를 검사한다. 공동 기록은 위 정책대로 보존한다. 저장소의 실제 삭제 실패나 결과를 모르는 PUT이 남으면 완료로 응답하지 않는다. 경과 시간만으로 미확정 업로드를 성공 처리하지 않는다.

BE が退会受け付けを永続保存し、CHAT・LL・BE データ・BE ファイルの整理を同じ作業番号で再試行する。受け付けたアカウントは直ちに無効化し、遅れて終わる要求や worker が情報を再保存できないよう各サービスの書き込み境界を検査する。共同記録は上記方針どおり保存する。ストレージの実削除失敗や結果不明の PUT が残れば、完了とは応答しない。経過時間だけで未確定アップロードを成功扱いしない。

BE는 `scripts/sql/20261023_account_deletion.sql` 및 `20261023_novel_account_deletion.sql`, LL은 `V042__account_deletion.sql`, CHAT은 최종 인계의 additive migration이 필요하다. 기존 DB migration이나 기록을 고치지 않는다. BE의 `account.deletion.enabled`와 `account.deletion.worker-enabled`는 모두 true여야 접수 가능하다. 기본값은 false다. CHAT의 소스 검증 guard와 feature flag, 각 서비스의 실제 capabilities 검사가 모두 충족돼야 활성화할 수 있다.

BE は `scripts/sql/20261023_account_deletion.sql` および `20261023_novel_account_deletion.sql`、LL は `V042__account_deletion.sql`、CHAT は最終引き継ぎの additive migration が必要である。既存 DB migration や記録は変更しない。BE の `account.deletion.enabled` と `account.deletion.worker-enabled` は両方 true でなければ受け付けできない。デフォルトは false である。CHAT のソース検証 guard と feature flag、各サービスの実際の capabilities 検査をすべて満たした後に有効化できる。

배포 담당은 기존 HTTP·worker·진행 중인 파일 쓰기를 종료하고 새 버전으로 교체한 사실을 확인한다. 보관된 옛 컨테이너가 수동 또는 예약 작업으로 다시 실행되는 경로도 통제한다. 과거의 개인 음성 파일 및 선택적 AI 영수증 디버그 파일은 실제 저장 범위와 메타데이터를 대조한다. 현재 프로세스의 파일 수가 0이라는 사실을 과거 모든 저장소가 비었다는 증거로 사용하지 않는다. 필요한 정리 근거가 없으면 활성화를 보류한다. 데이터 삭제 후 옛 이미지로 되돌리는 방식 대신 tombstone과 additive schema를 보존하는 전진 수정을 사용한다.

デプロイ担当は既存 HTTP・worker・進行中のファイル書き込みを終了し、新バージョンへ置き換えた事実を確認する。保存した古いコンテナーが手動または予約処理で再実行される経路も制御する。過去の個人音声ファイルと任意の AI 処理票デバッグファイルは、実際の保存範囲とメタデータを照合する。現在のプロセスのファイル数が 0 である事実を、過去の全ストレージが空という証拠にしない。必要な整理根拠がなければ有効化を保留する。データ削除後に古いイメージへ戻す方式ではなく、tombstone と additive schema を保存する前進修正を使う。

공개 HTTPS 경계는 기존 문의함 완료분 52패턴을 그대로 보존하면서 신고 1개, 본인 확인·접수 4개, 영수증 조회 1개, 관리자 조회·상태 3개의 정확한 패턴만 추가한다. 내부 서비스 삭제 API를 인터넷에 노출하지 않는다. 실제 적용 해시·서버 상태·이전 52패턴 보존은 배포 완료 영수증에서 확인한다.

公開 HTTPS 境界は既存の問い合わせボックス完了分 52 パターンをそのまま保存し、通報 1 個、本人確認・受け付け 4 個、処理票照会 1 個、管理者照会・状態 3 個の正確なパターンだけを追加する。内部サービスの削除 API はインターネットへ公開しない。実適用ハッシュ・サーバー状態・以前の 52 パターン維持はデプロイ完了記録で確認する。

## 검증 근거와 남은 확인

## 検証根拠と残る確認

중앙 근거는 `.codex-workspace/verification/shared/mobile-safety-deletion-20261023/`다. BE 집중·회귀 351개, LL 단위·HTTP·회귀 71개와 실제 격리 MySQL 4개, 모바일 전체 530개, FE 인증·BFF 79개가 통과했다. FE 공용 Desktop 실행기의 All 검증은 단위 592개와 빌드 성공이며, 마지막 영수증 충돌·요청 deadline 보완 이후 별도 최종 Build도 성공했다. 각 검증 사본 해시와 현재 소스 일치는 결과 JSON에 기록한다.

中央根拠は `.codex-workspace/verification/shared/mobile-safety-deletion-20261023/` である。BE の集中・回帰 351 件、LL 単体・HTTP・回帰 71 件と実際の隔離 MySQL 4 件、モバイル全体 530 件、FE 認証・BFF 79 件が合格した。FE 共用 Desktop 実行器の All 検証は単体 592 件とビルド成功であり、最後の処理票競合・要求 deadline 補強後の別途最終 Build も成功した。各検証コピーのハッシュと現在ソースの一致は結果 JSON に記録する。

웹 탈퇴 화면은 외부 연결을 차단한 loopback 합성 계정으로 headless E2E 4개를 통과했다. 본인 확인·정확한 ID 입력, 다른 계정 차단, 응답 유실 후 중복 전송 방지, 영수증 충돌과 로컬 삭제 후 서버 작업 보존을 확인했다. 실제 브라우저의 Google 로그인이나 실사용자의 탈퇴·삭제 완료를 검증한 것으로 확대하지 않는다. 모바일 웹 미리보기의 신고 취소·전송 횟수·영수증·320/390폭 표시도 확인했다. Android 키보드·스크린리더·이번 APK의 실제 기기 수락은 별도다.

ウェブ退会画面は外部接続を遮断した loopback の合成アカウントで headless E2E 4 件が合格した。本人確認・正確な ID 入力、別アカウントの拒否、応答喪失後の重複送信防止、処理票競合とローカル削除後のサーバー作業維持を確認した。実ブラウザーの Google ログインや実ユーザーの退会・削除完了を検証したという意味に拡大しない。モバイルのウェブプレビューにおける通報キャンセル・送信回数・処理票・320 / 390 幅表示も確認した。Android キーボード・スクリーンリーダー・今回 APK の実機受け入れは別である。

승인된 CHAT 26파일의 쓰기 잠금 배선은 실제 경합 24종 및 flags-off/on DI 2종을 통과했다. 그 과정에서 발견한 MySQL 잠금 승격 deadlock은 최초 upsert에서 배타 잠금을 얻도록 보완했다. 이미지 저장 도중 종료된 요청의 영속 기록과 늦은 WebSocket 프로필·알림 재전송 경계를 보완하고, 최종 Unit 264개·API 647개·실제 격리 MySQL 통합 402개, 총 1,313개를 실패·skip 없이 통과했다. 최종 CHAT 소스는 80파일이며 코드의 쓰기 경계 guard는 true, 운영 기능 flag 기본값은 false다.

承認済み CHAT 26 ファイルの書き込みロック配線は、実際の競合 24 種と flags-off / on DI 2 種で合格した。その過程で発見した MySQL ロック昇格 deadlock は、最初の upsert で排他ロックを取るよう補強した。画像保存途中に終了した要求の永続記録と、遅い WebSocket プロフィール・通知再送の境界を補強し、最終 Unit 264 件・API 647 件・実隔離 MySQL 統合 402 件、合計 1,313 件を失敗・skip なしで通過した。最終 CHAT ソースは 80 ファイル、コードの書き込み境界 guard は true、本番機能 flag のデフォルトは false である。

API 647개 결과는 공식 xUnit collection 직렬 설정으로 실행한 결과다. 앞선 병렬 실행에서는 첫 JWT·HTTP 준비와 테스트 간 자원 경합이 1초 요청 제한에 걸렸다. 응답 파서 fixture의 합성 JWT·JSON 준비만 예열했으며 제품 코드의 1초 제한이나 검증 조건은 바꾸지 않았다. 초기 실패, 두 번의 cold-start 진단과 최종 runner 설정·TRX를 모두 보존한다. 최종 인계의 정확한 커밋에 대해서도 필수 CI를 확인해야 한다. FE의 기존 Desktop·UI 검증은 관련 없는 기존 변경 7개가 함께 있던 작업 사본 기준이므로 그 변경을 임의 포함하지 않고 실제 배포 커밋을 다시 검증한다.

API 647 件は公式 xUnit collection 直列設定による実行結果である。先の並列実行では最初の JWT・HTTP 準備とテスト間のリソース競合が 1 秒の要求制限に達した。応答 parser fixture の合成 JWT・JSON 準備だけをウォームアップし、製品コードの 1 秒制限や検証条件は変えていない。初期失敗、2 回の cold-start 診断と最終 runner 設定・TRX をすべて保存する。最終引き継ぎの正確な commit に対しても必須 CI を確認する必要がある。FE の既存 Desktop・UI 検証は無関係な既存変更 7 件が混在する作業コピーを基準にしているため、その変更を勝手に含めず実デプロイ commit を再検証する。
