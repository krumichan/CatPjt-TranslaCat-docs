| 現セッションのログアウト | `POST /api/v1/auth/logout`、access Bearer、成功 body は `SUCCESS` |

신규 로그인은 독립적인 `sid`를 발급한다. 새 `auth_session`에는 refresh 원문 대신 hash와 만료·폐기 상태를 저장한다. `sid`는 JWT 내부와 BE 검증 경계에만 사용하고 기존 웹 DTO나 CHAT identity 응답에 임의 필드를 추가하지 않는다. refresh 원문 재사용 계약을 유지하여 기존 웹의 동시 갱신과 호환한다.

新規ログインは独立した `sid` を発行する。新しい `auth_session` には refresh 原文ではなく hash と期限・破棄状態を保存する。`sid` は JWT 内部と BE 検証境界でのみ使い、既存 web DTO や CHAT identity 応答に任意フィールドを追加しない。refresh 原文の再利用契約を維持し、既存 web の同時更新と互換にする。

구형 `sid` 없는 토큰은 기존 refresh 저장 계약으로 유효기간 동안 호환하며 신규 세션과 폐기를 격리한다. 구형 access 토큰에 새 세션의 즉시 폐기 보장을 소급한다고 표현하지 않는다. 추가 schema를 먼저 적용하고 기존 웹 로그인·갱신·로그아웃 회귀 검증을 함께 수행한다.

`sid` を持たない旧トークンは既存 refresh 保存契約で有効期限中は互換とし、新セッションと破棄を隔離する。旧 access token に新セッションの即時破棄保証を遡及すると表現しない。追加 schema を先に適用し、既存 web のログイン・更新・ログアウト回帰検証を併せて実施する。

## 앱 인증 경계

> 日本語：アプリの認証境界

- native refresh 자격은 서버 주소와 앱 환경에 따라 분리된 SecureStore에 보관한다. access는 메모리에만, 비밀번호는 로그인 요청에만 사용한다. 웹 미리보기의 refresh 저장은 메모리뿐이다.
  <br>日本語：native refresh 認証情報はサーバーアドレスとアプリ環境で分離した SecureStore に保存する。access はメモリ内のみ、パスワードはログイン要求にのみ使う。web プレビューの refresh 保存はメモリのみである。
- 갱신은 한 번에 하나만 실행한다. 일시적인 통신 실패와 확정된 인증 거절을 구분하고, 복원 실패 시 저장 자격을 무조건 삭제하지 않는다.
  <br>日本語：更新は一度に 1 件だけ実行する。一時的な通信失敗と確定した認証拒否を区別し、復元失敗時に保存済み認証情報を無条件で削除しない。
- 계정 세대가 바뀌면 이전 요청과 query cache를 정리한다. token 대기·HTTP 응답·JSON 처리 이후에도 세대를 검사하여 늦은 응답을 버린다.
  <br>日本語：アカウント世代が変わると旧要求と query cache を整理する。token 待機・HTTP 応答・JSON 処理後にも世代を検査して遅い応答を破棄する。
- 보호 API 401은 실제로 사용한 access가 현재 자격인 경우에만 폐기한다. 갱신된 access가 이미 있거나 갱신 중이면 이전 요청의 401로 새 자격을 지우지 않는다. 일반 API 403은 방 접근 거절일 수 있으므로 전역 로그아웃으로 처리하지 않는다.
  <br>日本語：保護 API の 401 は、実際に使用した access が現在の認証情報である場合にのみ破棄する。更新済み access がある、または更新中の場合、旧要求の 401 で新認証情報を消さない。通常 API の 403 は部屋アクセス拒否の可能性があるため全体ログアウトとして扱わない。
- 로그아웃은 먼저 로컬 화면과 연결을 해제하고, 만료된 access라면 캡처한 현재 세션의 refresh로 자격을 확인해 해당 sid만 폐기한다. 저장소 삭제나 서버 폐기가 실패하면 마무리 재시도를 제공한다.
  <br>日本語：ログアウトはまずローカル画面と接続を解除し、access が期限切れなら捕捉した現セッションの refresh で認証情報を確認してその sid のみ破棄する。ストレージ削除やサーバー側破棄が失敗した場合は、終了処理の再試行を提供する。
- 오류는 HTTP 상태와 허용한 인증 코드만 사용한다. 응답 원문·비밀번호·토큰을 오류 메시지와 로그에 반사하지 않는다.
  <br>日本語：エラーは HTTP 状態と許可した認証コードのみ使う。応答原文・パスワード・トークンをエラーメッセージやログに反射しない。

## 기존 Google 계정으로 앱에 로그인

> 日本語：既存 Google アカウントでアプリにログイン

사용자가 확인한 웹은 `https://translacat.vercel.app`이다. 앱은 외부 인증 브라우저에서 `/ko/mobile/sign-in?requestId=...`를 연다. Google에 새 native OAuth client를 등록하거나 기존 audience 검증을 완화하지 않고 기존 웹의 Google 로그인과 계정 ID를 사용한다.

ユーザーが確認した web は `https://translacat.vercel.app`。アプリは外部認証ブラウザーで `/ko/mobile/sign-in?requestId=...` を開く。Google に新 native OAuth client を登録したり既存 audience 検証を緩和したりせず、既存 web の Google ログインとアカウント ID を使う。

1. 앱이 서로 다른 난수로 verifier와 state를 만들고 S256 challenge를 전송해 유효기간 300초의 요청을 만든다. verifier는 앱 메모리에만 둔다.
   <br>日本語：アプリがそれぞれ異なる乱数で verifier と state を作り、S256 challenge を送信して有効期間 300 秒の要求を作成する。verifier はアプリメモリ内だけに置く。
2. 웹은 기존 Google 로그인 후 로그인한 계정을 보여 주고, 사용자가 명시적으로 앱 로그인을 승인해야 한다. FE 승인 route는 현재 세션·requestId에 묶인 CSRF와 Origin을 확인한다. 이어 별도 서버 전용 키로 요청을 서명하여 BE의 보호된 승인 API를 호출한다. 사용자 access 토큰만으로 새 기기 세션을 승인할 수는 없다.
   <br>日本語：web は既存 Google ログイン後にログイン中のアカウントを表示し、ユーザーがアプリログインを明示承認する必要がある。FE 承認 route は現セッション・requestId に結びつく CSRF と Origin を検査する。続いて別のサーバー専用キーで要求に署名し、BE の保護された承認 API を呼ぶ。ユーザー access token だけでは新しい端末セッションを承認できない。
3. BE는 고정 callback allowlist만 허용하고 최대 60초 유효한 일회 코드를 발급한다. 코드의 전체 유효기간은 최초 요청 만료를 넘지 않는다. DB에는 코드 hash만 저장한다.
   <br>日本語：BE は固定 callback allowlist のみ許可し、最大 60 秒有効の使い捨てコードを発行する。コードの全有効期間は最初の要求の期限を超えない。DB にはコードの hash だけ保存する。
4. callback에는 `code`, `state`, `requestId`만 전달한다. 앱은 정확한 scheme·host·path와 중복 query·state·요청 ID를 검사한 뒤 verifier로 교환한다. access·refresh와 비밀번호는 URL에 넣지 않는다.
   <br>日本語：callback には `code`、`state`、`requestId` だけを渡す。アプリは正確な scheme・host・path と重複 query・state・要求 ID を検査後、verifier で交換する。access・refresh とパスワードは URL に入れない。
5. BE는 행 잠금으로 코드와 증명을 한 번만 소비하고 앱을 위한 새 sid를 발급한다. 기존 웹 세션은 유지한다.
   <br>日本語：BE は行ロックでコードと証明を一度だけ消費し、アプリ用の新しい sid を発行する。既存 web セッションは維持する。

native 외부 브라우저 인증과 PKCE는 [RFC 8252](https://www.rfc-editor.org/rfc/rfc8252.html)와 [RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html)을 참고했다. Expo의 [WebBrowser](https://docs.expo.dev/versions/v58.0.0/sdk/webbrowser/)와 [Crypto](https://docs.expo.dev/versions/v58.0.0/sdk/crypto/)를 SDK 호환 버전으로 추가했다. 기존 Android APK에는 새 모듈이 없으므로 새 development build가 필요하다. 앱이 인증 도중 종료되어 verifier를 잃으면 새 로그인을 시작하며, 들어온 callback만으로 로그인하지 않는다.

native 外部ブラウザー認証と PKCE は [RFC 8252](https://www.rfc-editor.org/rfc/rfc8252.html) と [RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html) を参照した。Expo の [WebBrowser](https://docs.expo.dev/versions/v58.0.0/sdk/webbrowser/) と [Crypto](https://docs.expo.dev/versions/v58.0.0/sdk/crypto/) を SDK 互換版で追加した。既存 Android APK には新モジュールがないので新しい development build が必要である。認証中にアプリが終了して verifier を失ったら新しいログインを開始し、受け取った callback だけではログインしない。

현재 끝까지 일치하는 callback은 개발 앱의 `translacat-dev://auth/callback`이다. preview와 production용 scheme을 위한 설정 분리는 있으나, 웹 승인 화면과 BE allowlist까지 함께 확정한 상태가 아니므로 해당 환경의 Google 로그인은 지원 완료로 표시하지 않는다.

現在、端から端まで一致する callback は開発アプリの `translacat-dev://auth/callback`。preview/production 用 scheme の設定分離はあるが、web 承認画面と BE allowlist まで一緒に確定した状態ではないので、これらの環境の Google ログインを対応完了とは記載しない。

### 웹 서버의 승인 증명

> 日本語：web サーバーの承認証明

FE와 BE에 동일한 전용 `MOBILE_AUTH_APPROVAL_SECRET`을 설정해야 한다. 최소 32 UTF-8 bytes의 충분한 난수이며, `NEXTAUTH_SECRET`·JWT 서명 키와 공유하지 않는다. 모바일 소스·EXPO_PUBLIC 변수·callback·로그에는 넣지 않는다. 로컬 코드 검증 시점에는 실제 키를 만들지 않았고, 이후 사용자 지시에 따라 64 bytes 난수의 전용 키를 생성해 Windows 사용자 DPAPI로 암호화 보관했다. 2026년 10월 20일 사용자가 이전 중단 지시를 취소하고 이 개발 채팅의 설정 작업을 명시적으로 승인했다. 기존 보호 키를 다시 생성하지 않고 메모리에서만 복호화해 양쪽에 동일 원본을 등록했으며, 실제 값이나 키 hash는 출력하지 않았다. 설정 등록과 재배포 후 실제 기동 반영은 구분한다.

FE と BE に同じ専用 `MOBILE_AUTH_APPROVAL_SECRET` を設定する必要がある。最低 32 UTF-8 bytes の十分な乱数で、`NEXTAUTH_SECRET`・JWT 署名キーと共有しない。モバイルソース・EXPO_PUBLIC 変数・callback・ログに入れない。ローカルコード検証時点では実キーを作成しておらず、その後ユーザー指示で 64 bytes の乱数による専用キーを生成し、Windows ユーザー DPAPI で暗号化して保存した。2026 年 10 月 20 日、ユーザーは以前の中止指示を取り消し、この開発チャットの設定作業を明示承認した。既存の保護済みキーは再生成せずメモリ内だけで復号し、両側に同一原本を登録し、実値やキー hash は出力していない。設定登録と再デプロイ後の実起動への反映は区別する。

FE는 `X-Mobile-Approval-Timestamp`에 Unix 초를, `X-Mobile-Approval-Signature`에 HMAC-SHA256의 소문자 hex를 보낸다. 서명 대상은 아래 여섯 줄을 LF로 연결한 문자열이며 마지막 줄바꿈은 없다.

FE は `X-Mobile-Approval-Timestamp` に Unix 秒、`X-Mobile-Approval-Signature` に HMAC-SHA256 の小文字 hex を送る。署名対象は以下の 6 行を LF で連結した文字列で、末尾改行はない。コード内の韓国語説明行は順に、正規化した小文字 requestId UUID、Bearer 接頭辞を除いた正確な accessToken の SHA-256 小文字 hex、Unix timestamp 秒を意味する。

~~~text
mobile-auth-approval-v1
POST
/api/v1/auth/mobile/authorize
정규화된 소문자 requestId UUID
Bearer 접두사를 제외한 정확한 accessToken의 SHA-256 소문자 hex
Unix timestamp 초
~~~

BE는 ±60초 범위와 상수 시간 비교를 확인한 뒤에만 승인 서비스를 호출한다. 설정이 없거나 짧으면 모바일 승인만 `503 MOBILE_AUTH_NOT_CONFIGURED`, 증명이 없거나 틀리면 `401 MOBILE_AUTH_APPROVAL_INVALID`다. 기존 Google·이메일 로그인은 이 새 설정을 요구하지 않는다. FE 화면도 설정이 준비되지 않았으면 Google 로그인을 시작하기 전에 안내한다.

BE は ±60 秒の範囲と定数時間比較を確認してからのみ承認サービスを呼ぶ。設定が未指定または短ければモバイル承認だけが `503 MOBILE_AUTH_NOT_CONFIGURED`、証明がない/不正なら `401 MOBILE_AUTH_APPROVAL_INVALID` となる。既存 Google・メールログインはこの新設定を要しない。FE 画面も設定未準備なら Google ログイン開始前に案内する。

## 채팅 전송과 수신

> 日本語：チャットの送信と受信

API base는 공개 BE의 `/api/v1`까지 지정한다. WebSocket은 같은 공개 origin의 `/ws/chat`이며 토큰은 URL에 넣지 않고 STOMP CONNECT Authorization으로 전달한다. 재연결마다 token provider를 다시 호출한다.

API base は公開 BE の `/api/v1` まで指定する。WebSocket は同じ公開 origin の `/ws/chat` で、トークンは URL に入れず STOMP CONNECT Authorization で渡す。再接続のたびに token provider を再呼び出しする。

일시적인 인증 조회·네트워크 실패에는 취소 가능한 지수 backoff로 다시 연결한다. 로그아웃·계정 전환·화면 해제는 예약된 재시도와 늦은 응답까지 취소한다. 확정된 인증 거절과 STOMP 거절은 무한 재시도하지 않는다. 기존 웹의 두 채팅 WebSocket도 연결할 때마다 최신 세션을 조회하도록 함께 수정한다.

一時的な認証照会・ネットワーク失敗では、取消可能な指数 backoff で再接続する。ログアウト・アカウント切り替え・画面解除では予約再試行と遅い応答まで取り消す。確定した認証拒否・STOMP 拒否を無限再試行しない。既存 web の 2 つのチャット WebSocket も、接続ごとに最新セッションを取得するよう併せて変更する。

기존 메시지 생성에는 clientMessageId나 멱등 키가 없다. 따라서 REST 저장 응답으로 성공을 판단하고, 요청 중 연결이 끊겼다면 자동 재전송하지 않는다. 결과가 불명확한 메시지를 사용자가 중복 전송하지 않도록 조회 후 확인을 안내한다. 멱등 전송 키는 후속 서버 계약이다.

既存メッセージ作成には clientMessageId や冪等キーがない。そのため REST 保存応答で成功を判断し、要求中に接続が切れても自動再送しない。結果が不明なメッセージをユーザーが重複送信しないよう、照会して確認するよう案内する。冪等送信キーは後続のサーバー契約である。

초기 이력과 STOMP 사이의 누락은 after 조회를 끝까지 따라가며 복구한다. 이벤트는 서버 ID로 병합하고 번역·읽음·방 권한 상태를 재조회한다. 숫자 wire ID는 안전 정수 범위를 먼저 검사하며, 범위를 벗어난 숫자를 문자열 변환만으로 복구했다고 처리하지 않는다. 읽음은 앱 활성·방 focus와 실제 메시지 노출을 함께 확인한다.

初期履歴と STOMP の間の欠落は after 照会を最後まで追って復旧する。イベントはサーバー ID で統合し、翻訳・既読・部屋権限状態を再照会する。数値 wire ID は安全整数範囲を先に検査し、範囲外の数値を文字列変換だけで復旧できたとは扱わない。既読はアプリがアクティブ・部屋が focus 中であることと、実際のメッセージ露出を併せて確認する。
