Build는 `NoGameplay`를 명시해야 한다. 이 프로필에서 게임·Editor UI·GPU 에셋 작업·실제 DB/API 서비스 시작·브라우저/PC 화면 조작을 실행하지 않는다. 게임 프로세스를 띄우는 검사는 Build로 분류하지 않는다. 무인 엔진 컴파일도 실제 클라이언트·Editor UI를 시작하지 않는지 어댑터를 확인한다.

Buildでは`NoGameplay`を明示しなければならない。このプロファイルではゲーム・Editor UI・GPUアセット作業・実際のDB/APIサービス開始・ブラウザー/PC画面操作を実行しない。ゲームプロセスを起動する検査はBuildに分類しない。無人のエンジンコンパイルでも、実際のクライアント・Editor UIを開始しないかアダプターを確認する。

시작 전에 CPU·사용 가능 RAM·commit·GPU 사용률·사용/여유 VRAM·디스크 여유를 확인하고 작업별 예산을 예약한다. 빌드 CPU25%·메모리2048MiB는 보수적 시작값이며, 플레이는 서버와 복수 클라이언트를 합친 실제 사용량·예상 peak를 반영한다. CPU 10%, 물리 RAM2GiB·commit1GiB, 시스템용 RAM3GiB, 예상 디스크 증가를 제외한 여유5GiB는 검증하며 조정할 보수적 제안값이다. GPU/VRAM 예약에도 여유를 남기고 측정 불가 시 충분하다고 가정하지 않는다. GPU·디스크 IO의 전역 강제 상한을 구현한 것으로 표시하지 않는다. 작업 세트 수와 창 수 자체를 플레이 금지 기준으로 삼지 않는다.

開始前にCPU・利用可能RAM・commit・GPU使用率・使用中/空きVRAM・ディスク空きを確認し、作業ごとの予算を予約する。ビルドのCPU25%・メモリ2048MiBは保守的な開始値で、プレイにはサーバーと複数クライアントの合計実使用量・予想peakを反映する。CPU10%、物理RAM2GiB・commit1GiB、システム用RAM3GiB、予想ディスク増加を除いた空き5GiBは、検証しながら調整する保守的な提案値。GPU/VRAM予約にも余裕を残し、測定不能なら十分とは仮定しない。GPU・ディスクIOの全体強制上限を実装したとは表示しない。作業セット数やウィンドウ数自体をプレイ禁止の基準にしない。

## 구현 범위와 보존 조건 / 実装範囲と保全条件

1. 새 작업에서 명시적으로 선택하는 Build/Play 자원 예약을 추가하고, 기존 인자·기본 Exclusive와 실행 중인 작업은 보존한다. 전역 플레이 배타 게이트를 두지 않고 상태 조회에 작업별 ID·프로필·예산·충돌 자원 소유권을 표시한다.

   新規作業で明示的に選択するBuild/Playリソース予約を追加し、既存引数・既定のExclusiveと実行中の作業を保全する。全体プレイ排他ゲートは設けず、状態照会に各作業のID・プロファイル・予算・競合リソース所有権を表示する。
2. 새 병행 작업은 호환 공유 게이트와 데이터·포트·입력·작업 폴더 등 실제로 겹치는 자원별 소유권을 확보한다. 다른 게임이라는 이유로 상호 배제하거나 창 수로 차단하지 않는다. 공유 키보드/마우스를 쓰는 작업과 독립된 창·게임 입력을 쓰는 작업의 충돌을 구분한다. 이미 실행 중인 이전 버전 작업의 배타적 파일 핸들은 유지하고 완료 전에는 우회하지 않는다. 잠금 삭제·소유권 탈취를 하지 않는다.

   新しい並行作業は互換共有ゲートと、データ・ポート・入力・作業フォルダーなど実際に重なるリソース別の所有権を確保する。異なるゲームという理由で相互排除せず、ウィンドウ数でも遮断しない。共有キーボード/マウスを使う作業と、独立したウィンドウ・ゲーム入力を使う作業の競合を区別する。実行中の旧バージョン作業の排他的ファイルハンドルを保持し、完了前に迂回しない。ロック削除・所有権奪取は行わない。
3. 빌드의 CPU/메모리 상한은 **새로 시작하는 전용 worker와 그 자식**에만 Windows Job Object로 적용하는 안이다. 기존 프로세스·다른 작업·전역 환경에는 적용하지 않는다. 설정에 실패하면 새 작업을 시작하지 않는다. 메모리 상한은 전용 commit 제한이며 초과한 작업은 할당 실패로 실패할 수 있다. 플레이의 CPU/RAM/GPU/VRAM 예산은 입장 판단용이며 모든 외부 대화형 프로세스에 강제 상한이 적용됐다고 주장하지 않는다.

   ビルドのCPU/メモリ上限は、**新しく開始する専用workerとその子**だけにWindows Job Objectで適用する案とする。既存プロセス・他作業・グローバル環境には適用しない。設定できなければ新規作業を開始しない。メモリ上限は専用commitの制限で、超過した作業は割り当て失敗によって失敗し得る。プレイのCPU/RAM/GPU/VRAM予算は開始可否の判断用で、外部の対話型プロセスすべてに強制上限が適用されたとは主張しない。
4. **자동 프로세스 종료 기능은 넣지 않는다.** `TerminateProcess`, `TerminateJobObject`, 종료 시 자식 자동 제거 옵션을 사용하지 않는다. 하위 작업이 남아 있으면 예약과 대기를 유지하고 상태를 보고한다. 컴파일 서버/daemon 재사용을 끄는 어댑터 옵션을 사용한다.

   **プロセスの自動終了機能は追加しない。** `TerminateProcess`、`TerminateJobObject`、終了時の子の自動削除オプションは使わない。下位作業が残っている場合は予約と待機を維持して状態を報告する。コンパイルサーバー/daemonの再利用を無効にするアダプターオプションを使う。
5. 결과에 사용 프로필·예산·시작 전 자원·실제 종료 코드·메모리 peak를 기록하고 기존 소스 해시 검증·JobId·결과 회수·SSH 인증을 유지한다. 자원 부족은 미시작 상태로 반환하고 자동 재시작·노트북 fallback을 하지 않는다.

   使用したプロファイル・予算・開始前のリソース・実際の終了コード・メモリpeakを結果に記録し、既存のソースハッシュ検証・JobId・結果回収・SSH認証を維持する。リソース不足は未開始状態として返し、自動再起動・ノートPCへのfallbackは行わない。
6. 기존 FE 실행기도 명시적인 Build 프로필을 호출하도록 연결한 뒤 검증한다. Unity/Unreal의 대화형 브리지나 외부 서비스는 일반 자식 상속만으로 제한된다고 가정하지 않는다. 해당 어댑터가 신규 전용 실행 주체와 완료 상태를 보장하기 전에는 Exclusive를 유지한다.

   既存FE実行器も、明示的なBuildプロファイルを呼ぶように接続してから検証する。Unity/Unrealの対話型ブリッジや外部サービスが、通常の子プロセス継承だけで制限されるとは仮定しない。該当アダプターが新規専用実行主体と完了状態を保証するまではExclusiveを維持する。
